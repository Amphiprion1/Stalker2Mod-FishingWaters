Graphes à poser

1. Enum EFW_ActiveBait dans Content : None, Worm, Meat.
2. BP_FlishableWaters. La variable ActiveBait est déjà là et sert au filtre string RequiredBaitSID. Passe son type à EFW_ActiveBait, défaut None. Rebranche les pins cassés du match : compare le nom de l’enum (None / Worm / Meat) au tableau RequiredBaitSID.
   • SetActiveBait(NewBait) : Set ActiveBait = NewBait. Rien d’autre.
   • GetActiveBait() : retourne ActiveBait.
   • StartFishingSession lit GetActiveBait() et ne le remet pas à None.
   • EndFishingSession(Success) seulement : SetActiveBait(None). Pas de second item retiré de l’inventaire.
   • None : pas de poisson, toast déjà prévu sid_fw_feedback_DenyNoBait (« Pas d'appât. »).
   • Worm / Meat : le filtre existant. Sur les lignes de zone, mets Worm dans RequiredBaitSID des communs et Meat sur la faune agressive. Aujourd’hui la zone n’a que FWPerch.
3. Shakes. Duplique BP_FW_FishingRodUse en BP_FW_Shake_BaitWorm et BP_FW_Shake_BaitMeat (parent LegacyCameraShake). Dans Receive Play Shake, remplace l’appel StartFishingSession :
   • Get All Actors of Class → BP_FlishableWaters → Get index 0
   • SetActiveBait(Worm) ou SetActiveBait(Meat)
   • Print String ActiveBait=Worm ou ActiveBait=Meat (écran + log)
   • Dans les defaults du shake, amplitude de toutes les oscillations à 0.

Le tir de la canne continue de passer par BP_FW_FishingRodUse → StartFishingSession. Un appât ne lance pas la pêche.
