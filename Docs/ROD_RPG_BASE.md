# Rod rebase onto RPG-7U (GunRpg7_GL)

Date: 2026-09-24

## Why RPG base

UDP pistol clone forced a detachable mag (GunUDP_MagDefault). Custom mag SID broke the AnimBP montage and caused an ~8 s reload wait. RPG-7U already has:

- `MaxAmmo = 1`
- `WeaponReloadTimePerAttachment[0].AttachPrototypeSID = empty` (no magazine)
- `ReloadTypes = Full` only

So the rod gets native capacity 1 with no mag attach, while keeping SID `FW_FishingRod_Wep` (Blueprints / `FW_FishingRodShake` / loc / `FW_Bait` keep working).

## How bait types work

Weapon `AmmoTypeProjectiles` maps ammo type -> projectile:

- `[0] Default` -> projectile `empty`
- `[1] ArmorPiercing` -> projectile `empty`

Ammo items set `AmmoType`:

- `FW_Bait` = `EAmmoType::Default`
- `FW_Bait_B` = `EAmmoType::ArmorPiercing`

Engine allows at most four types seen in vanilla: **Default**, **ArmorPiercing**, **Expanding**, **Supersonic** (plus None unused for real ammo). Switch in-game with the normal weapon ammo-type key.

## Harmless projectile

Vanilla `ProjectilePrototypes.cfg` has SID `empty` (Speed=0, small BP). Damage is already 0 on player settings + `DamageMod` on bait. We did **not** add `FW_BaitProjectile`: ProjectilePrototypes is a single vanilla root cfg and is not listed in this mod's known ModGameData merge folders. Never use `PPG7V` (exploding RPG rocket).

## Known risks

- `AmmoCaliber=A045` kept for loc/HUD -> vanilla .45 ammo may still load into the rod.
- FP mesh is `rpg7_Skeletal` until a custom rod skeleton / AnimBP exists (looks like RPG in hands).
- `WeaponStaticMeshParts` cleared with empty `{bskipref}` (same pattern as empty PreinstalledAttachments). If a rocket still shows, report and we revisit.
- Unverified whether Blueprint can read which bait type is loaded.
- Rod may move to a rifle/launcher slot (was pistol via UDP).
