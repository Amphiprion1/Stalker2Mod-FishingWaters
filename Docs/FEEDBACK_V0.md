# Feedback UI v0 — toast + LocDB SIDs

Goal: same info as today's Prints, but a short on-screen toast (S2-looking), with **text from the mod LocDB** (not hardcoded FR/EN in BP).

## Channels (keep separate)

| Channel | Use |
|---------|-----|
| `WBP_FW_Toast` | Runtime: deny, bite, fail, abort, success one-liners |
| `PDATutorialPrototypes` | Later: teach controls **once** (not every cast) |
| Sound | Pair with toast (distinct cues per kind) |

Do **not** open a full PDA tutorial for "pas d'eau" / every abort.

## Architecture

One function on `BP_FlishableWaters`:

`ShowFWFeedback(Kind: EFW_FeedbackKind, OptText: String)`

1. Soft-deny cooldown: if Kind is Deny* and last deny toast < cooldown → return.
2. Resolve text:
   - If OptText non-empty → use as debug override (FText from string).
   - Else Kind → SID (`sid_fw_feedback_<KindName>`) → **localized FText from LocDB**.
3. Create `WBP_FW_Toast` → `Setup(ResolvedText, Kind)` → AddToViewport.
4. Widget auto-removes after Duration (default ~2 s). Optional Sound by Kind later.

### Recommendation: who resolves the SID?

**Resolve SID → FText in `ShowFWFeedback` (caller). Pass `FText` into `WBP_FW_Toast`.**

| Approach | Verdict |
|----------|---------|
| Caller resolves SID → FText; WBP `Setup(Text, Kind)` | **Preferred** — toast stays dumb; OptText override easy; style still from Kind |
| WBP `Setup(SID, Kind)` resolves inside | OK if you want one place for loc lookup; OptText then needs a second path |

Do **not** hardcode French/English `Make Literal String` for player-facing lines.

### Loc lookup node (bait / LocDB)

Same pipeline as inventory names for `sid_items_FW_Bait_short_name`:

1. SID string (e.g. `sid_fw_feedback_DenyNoWater`) must exist as a **row** in `LOC_Mod_FishableWaters`.
2. After save, it must appear in `Autogenerated_*_LocalizationDatabase` (if HUD still shows raw SID for bait, LocDB is stale — refresh first).
3. In BP, use the **same localization / Get-text-from-SID path you already trust for item loc** once bait shows "Appât" instead of the raw SID. Typical search in ModEditor context menu: Localization, Localized, SID, LocDB, Get Text. If no free BP node is exposed, temporary fallback: store FText defaults on a DataTable keyed by Kind — but **target is LocDB SIDs**.

Map `EFW_FishingEnding` → Kind inside `EndFishingSession` (Success / FailStamina / FailTimeout / AbortMove / AbortDamage / AbortPDA / …).

Cast gate (no water hit) → `DenyNoWater` instead of Print.

## Click-path: Gerald in ModEditor

### A) Loc rows (do this first)

1. Open `FishableWaters` → `Content/DataTables/LOC_Mod_FishableWaters`.
2. For each row in the SID table above (or copy from `ModGameData/FishableWaters/Localization/FW_Feedback_Loc_stub.cfg`):
   - Add row, **Row Name** = full SID (e.g. `sid_fw_feedback_DenyNoWater`).
   - Set **French** = FR string, **English** = EN string (`LanguagesToLocalizedStrings` / `ELocalizationLanguage`).
3. Save LOC asset.
4. **LocDB refresh** (required — same as bait): regenerate / resave so `Content/Autogenerated_*_LocalizationDatabase` lists the new SIDs. Verify in LocDB that `sid_fw_feedback_DenyNoWater` appears (and that bait SIDs like `sid_items_FW_Bait_short_name` are still present).
5. Cook / package mod as you usually do after loc changes.

### B) Enum `EFW_FeedbackKind` (if not created)

1. Content Browser → right-click → Blueprint → **Enumeration** (or under `Content/Enums` if you keep enums there).
2. Name: `EFW_FeedbackKind`.
3. Add enumerators exactly: `DenyNoWater`, `DenyNoBait`, `DenyBusy`, `Bite`, `PromptFight`, `Success`, `FailStamina`, `FailTimeout`, `AbortMove`, `AbortDamage`, `AbortPDA`, `AbortBusy`.
4. Compile / Save.

### C) Widget `WBP_FW_Toast` (already created at `Content/UI/WBP_FW_Toast`)

Layout:
- Fullscreen canvas, **bottom-center** anchor.
- Vertical box: optional thin icon spacer + `TextBlock` (white / off-white, outline or shadow).
- Size ~ mid screen width max 500, wrap text.
- No buttons, not focusable, `Visibility = HitTestInvisible`.

Graph:
1. Variables: `Message` (Text), `Kind` (`EFW_FeedbackKind` or byte), `Duration` (float, default 2.0).
2. Custom event / function **`Setup(InText: Text, InKind: EFW_FeedbackKind)`** (preferred — **FText from caller**, not SID):
   - Set Message, Kind.
   - Set TextBlock ← Message.
   - Color by Kind: Deny* → orange/red; Bite / PromptFight → amber; Success → soft green; Fail* / Abort* → muted red.
3. On added to viewport (or end of Setup): Set Timer by Event → Duration → RemoveFromParent (fade optional later).
4. Do **not** resolve Loc SID inside the widget unless you deliberately chose that approach.

### D) `ShowFWFeedback` on `BP_FlishableWaters`

1. Open `BP_FlishableWaters`.
2. Variables:
   - `bFWDebugPrint` (bool, **default false**).
   - `LastDenyToastTime` (float) or per-kind cooldown tracking.
   - Optional: `DenyCooldown` = 2.5.
3. Function **`ShowFWFeedback(Kind, OptText)`**:
   - **Cooldown**: if Kind is DenyNoWater / DenyNoBait / DenyBusy → if `Now - LastDenyToastTime < Cooldown` → return; else update LastDenyToastTime.
   - **SID map**: Switch on Kind → String SID (`sid_fw_feedback_…` from table).
   - **Text**: if OptText not empty → FText from OptText; else LocDB lookup by SID → FText.
   - **Create Widget** `WBP_FW_Toast` (owning player) → `Setup(Text, Kind)` → `Add to Viewport`.
   - Optional: if `bFWDebugPrint` → also Print String (debug only).
4. Replace every **player-facing** Print with `ShowFWFeedback(Kind)`.
5. Gate remaining debug Prints with `bFWDebugPrint`.

Call sites:
- Cast blocked (no water / no bait / busy) → Deny*
- Enter Fight / bite → Bite; optional PromptFight once
- `EndFishingSession(Reason)` → map ending → Kind → Success / Fail* / Abort*

## Build order

1. Add feedback SIDs to `LOC_Mod_FishableWaters` + LocDB refresh (stub file for copy).
2. Create `EFW_FeedbackKind` if missing; finish `WBP_FW_Toast.Setup(Text, Kind)`.
3. `ShowFWFeedback` + Deny* cooldown + Kind→SID→loc→toast.
4. Swap EndFishingSession Prints → Kind map.
5. Swap cast-deny Print → DenyNoWater.
6. PIE: dirt cast, water cast, abort move, success — toast only, no Print spam.
7. Later: PDA tutorial once + sounds.

## PIE checklist

- [ ] LocDB contains `sid_fw_feedback_*` (and bait SIDs still OK)
- [ ] Dirt cast → one toast ("Pas d'eau ici."), no stack spam if mash Fire
- [ ] Water cast → no deny toast
- [ ] Fight → bite or prompt toast once
- [ ] AbortMove / PDA / damage → matching localized line
- [ ] Success → "Pris !" + loot still works
- [ ] Game language FR vs EN swaps toast language via LocDB
- [ ] `bFWDebugPrint = false` → no player-facing Print spam

## Contextual Legend

**Verdict: NO for FishableWaters v0 runtime feedback** — do not drive vanilla Contextual Legend from the mod. Keep `WBP_FW_Toast`. PDA tutorials stay one-shot later.

### What it is

| Name | Evidence |
|------|----------|
| Live HUD class | `W_GameHUD` (`/Game/GameLite/FPS_Game/UIRemaster/HUD/W_GameHUD`) via `HUDWidgetClass` in `CoreVariables.cfg` / `AssetLibrary.cfg` |
| Child property on HUD | `ContextualLegend` (sibling of `SystemNotification`, `AmmoPanel`, `HoldBreathHint`, `OffsetAimingHint`, …) |
| C++ widget type | `UHUDContextualLegend` — header path baked in ModEditor: `UI/HUD/HUDContextualLegend.h` |
| Nearby fields (binary) | `LegendText`, `DropDeadBodyHintSID`, `GuitarPCAHintSID`, `bShowLegend`, `HintSIDs` / `HintSIDs_Key`, `InactiveHintTransparency` |
| Example hint SID | `sid_misc_hint_dropdeadbody` (from `DropDeadBodyHintSID` default string in shipping binary) |
| UMG look | Left text + key glyph + right text (designer preview placeholders like "Some info" / Esc / "some text") |

**Related but different channels (do not confuse):**

| Channel | Path / type | Role |
|---------|-------------|------|
| Interact prompt UI | `W_InteractView` (`InteractWidgetClass`) | World interact dots / hold progress — not Contextual Legend |
| System notifications | `USystemNotificationWidget` (HUD child `SystemNotification`) | Quest/tip/news toasts; setting `ShowSystemNotification`; cfg `UserNotificationPrototypes` (`EUserNotificationType::SideText` etc.) |
| PDA / map "ShowLegendHint" | World-map / PDA hint box (`ContextualHintsBox`) | Map legend — **not** HUD Contextual Legend |
| PDA tutorials | `PDATutorialPrototypes.cfg` + `AutonomicTutorial` / `ReferenceTutorial` / `SplashTutorial` widget classes | One-shot teach controls (`PDATutorialNoteSID` from quests) |

### Public BP Set API?

**None found** for free-form left/key/right text from Blueprint.

- No documented `SetText` / `ShowHint` / `PushLegend` callable for mods in GameLite cfg or ModEditor reflection strings around `UHUDContextualLegend`.
- Legend appears **owned by the live game HUD** and fed by the **interaction / hint-SID system** (loc SIDs + `HintSIDs` map), not a general toast API.
- GameLite on this ZoneKit install is **cfg-only** (`Content\GameLite\GameData`); FPS_Game UI assets are not unpacked — no designer export of widget functions to read.

### WARN: Create Widget `W_GameHUD`

**Do not** `Create Widget` → `W_GameHUD` → Get `ContextualLegend` at runtime.

That builds a **second orphan HUD**, not the player's live HUD. Almost certainly wrong (duplicate UI, no game subsystems wired). The real instance is spawned by the game from `HUDWidgetClass`.

### Optional editor discovery only (not v0 path)

If you still want to inspect what BP exposes on the *live* instance (read-only experiment):

1. `Get Player Controller` → try Get HUD / get all widgets of class `W_GameHUD` already in viewport (do **not** Create).
2. Get property `ContextualLegend`.
3. In Details / context menu, list Blueprint-callable functions — expect none useful for arbitrary fishing strings.
4. Do **not** ship Create-`W_GameHUD` code.
